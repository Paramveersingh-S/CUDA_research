\section{Methodology}
\label{sec:methodology}

\subsection{System Architecture}
The GreenTune framework intercepts the standard Triton kernel compilation pipeline. Rather than executing a blind grid search for the fastest configuration, GreenTune injects an \texttt{EnergyAutotuner} that wraps the benchmarking loop. Figure \ref{fig:architecture} illustrates the system architecture.

\subsection{Continuous Power Integration}
Because NVML reports board power at a fixed sampling frequency (typically 10-60 Hz depending on the driver version), taking a single power sample per benchmark trial is statistically invalid. GreenTune employs a \texttt{PowerSampler} that runs continuously on an asynchronous Python thread. During the execution of $N$ benchmark trials for a specific kernel configuration, the sampler continuously polls \texttt{nvmlDeviceGetPowerUsage()}. Once the benchmark completes, the instantaneous power samples (in Watts) are integrated using the trapezoidal rule over the total execution time (in seconds) to compute the total energy (in Joules).

\subsection{Pareto Extraction and Multi-Objective Search}
For each tensor shape, the \texttt{EnergyAutotuner} collects the median latency $L_c$ and the mean energy per call $E_c$ for every configuration $c$ in the search space. A configuration $c$ dominates another configuration $c'$ if $L_c \leq L_{c'}$ and $E_c \leq E_{c'}$, with at least one strict inequality. The set of non-dominated configurations forms the Pareto frontier.

To mitigate the exponential cost of exhaustive grid searching across massive configuration spaces (e.g., Tiled GEMM), GreenTune supports multi-objective optimization using the Tree-structured Parzen Estimator (TPE) via the Optuna library. This replaces the exhaustive sweep with an intelligent search, dramatically reducing the on-device benchmarking budget required to approximate the Pareto knee.
